## 二、Docker 一键部署（推荐）

### 1. 准备工作

安装 Docker Desktop，启动后等待状态显示 `Engine running`。

检查：

```powershell
docker --version
docker compose version
docker info
```

### 2. 使用一键 Docker 运行 `.bat`

进入项目根目录：

```text
E:\2026-2\Java EE\税务业务管理-Spring Boot 3.5 +vue3版本
```

推荐双击：

```text
START.bat
```

兼容入口：

```text
docker-start.bat
```

两个 `.bat` 都调用：

```text
scripts\start-docker.ps1
```

启动脚本会自动：

1. 检查 Docker 和 Docker Compose。
2. 构建 Spring Boot 后端镜像。
3. 构建 Vue 前端并复制到 Nginx 镜像。
4. 启动 MySQL 8。
5. 等待 MySQL 健康检查通过。
6. 启动 Spring Boot 后端。
7. 等待 `/actuator/health` 返回 `UP`。
8. 启动 Nginx 前端容器。
9. 输出容器状态和访问地址。
10. 自动打开系统首页。

登录页提供同一行的“账号登录 / 注册账号 / 角色说明”三个页签。注册成功后返回登录页并自动预填账号。

首次运行需要下载镜像、Maven 依赖和 npm 依赖，通常需要数分钟。后续再次运行会明显加快。

### 3. 命令行启动

在项目根目录执行：

```powershell
docker compose up -d --build
```

查看状态：

```powershell
docker compose ps
```

查看全部日志：

```powershell
docker compose logs -f --tail=200
```

分别查看：

```powershell
docker compose logs -f --tail=200 backend
docker compose logs -f --tail=200 frontend
docker compose logs -f --tail=200 mysql
```

停止并保留数据：

```powershell
docker compose down
```

也可以双击：

```text
docker-stop.bat
```

实时查看日志也可以双击：

```text
docker-logs.bat
```

### 4. 默认访问地址

| 服务 | 地址 |
| --- | --- |
| 系统页面 | <http://localhost:18080> |
| Spring Boot 后端健康检查 | <http://localhost:18081/actuator/health> |
| Swagger UI | <http://localhost:18081/swagger-ui.html> |
| MySQL | 仅 Docker 内部网络访问，不开放宿主机端口 |

18080/18081 是 Docker 默认端口，与本地开发时的 5173/8080 不同。

### 5. Docker 架构和容器

```text
Browser
  → http://localhost:18080
  → tax-frontend（Nginx）
  → /api 转发到 tax-backend:8080
  → tax-backend（Spring Boot）
  → tax-mysql:3306
```

| 名称 | 用途 |
| --- | --- |
| `tax-frontend` | Vue 构建产物 + Nginx |
| `tax-backend` | Spring Boot 后端 API |
| `tax-mysql` | MySQL 8 |
| `tax-business-network` | Docker 内部网络 |
| `tax-business-mysql-data` | MySQL 持久化数据卷 |

Nginx 负责：

- 提供 Vue SPA 静态页面。
- 将 `/api/` 转发给 Spring Boot。
- 将 `/actuator/` 转发给 Spring Boot。
- 支持 Vue Router history 模式的页面回退。

### 6. 数据库初始化

不需要手工导入 SQL。Spring Boot 启动时 Flyway 自动执行：

```text
backend/src/main/resources/db/migration/V1__init_schema.sql
backend/src/main/resources/db/migration/V2__seed_demo_data.sql
```

只有 MySQL 数据卷第一次创建时才会执行数据库初始化。删除容器但保留数据卷后，Flyway 也会根据迁移历史避免重复插入种子数据。

### 7. 修改端口与数据库密码

复制配置模板：

```powershell
Copy-Item .env.docker.example .env
```

编辑 `.env`：

```dotenv
APP_PORT=18080
BACKEND_PORT=18081

MYSQL_DATABASE=tax_business
MYSQL_USER=tax_app
MYSQL_PASSWORD=TaxDemo_2026
MYSQL_ROOT_PASSWORD=TaxRoot_2026

EXPORT_MAX_ROWS=5000
```

修改后重新执行：

```powershell
docker compose up -d --build
```

例如改成：

```dotenv
APP_PORT=28080
BACKEND_PORT=28081
```

访问：

```text
http://localhost:28080
```

`.env` 已被 `.gitignore` 忽略，不要提交真实密码。

### 8. 更新、停止与重启

停止但保留数据：

```powershell
docker compose down
```

启动已有容器：

```powershell
docker compose start
```

修改 Java、Vue、Nginx 或配置后重新构建：

```powershell
docker compose up -d --build
```

查看单个后端日志：

```powershell
docker compose logs -f --tail=200 backend
```

### 9. 重置演示数据

```powershell
docker compose down -v
docker compose up -d --build
```

> 警告：`down -v` 会删除 `tax-business-mysql-data`，旧数据不可恢复，只用于重置演示环境。

## 三、传统本地开发部署

这里的“传统”指不使用 Docker，而是在 Windows 本机分别启动 MySQL、Spring Boot 后端和 Vue 开发服务器。适合课程演示、代码调试和查看前后端分离过程。

### 1. 安装前置软件

| 软件 | 建议版本 |
| --- | --- |
| JDK | 17 |
| Maven | 3.9+ |
| MySQL | 8.0+ |
| Node.js | 20+ |
| npm | 随 Node.js 安装 |

检查：

```powershell
java -version
mvn -version
mysql --version
node --version
npm --version
```

### 2. 创建数据库和账号

使用 MySQL 管理员账号登录：

```powershell
mysql -u root -p
```

执行：

```sql
CREATE DATABASE tax_business
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'tax_app'@'localhost'
  IDENTIFIED BY 'ChangeMe_Local_2026';

GRANT ALL PRIVILEGES ON tax_business.* TO 'tax_app'@'localhost';
FLUSH PRIVILEGES;
```

如果只部署，不运行后端自动化测试，可以不创建 `tax_business_test`。若要运行测试，则另外创建：

```sql
CREATE DATABASE tax_business_test
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

GRANT ALL PRIVILEGES ON tax_business_test.* TO 'tax_app'@'localhost';
FLUSH PRIVILEGES;
```

表结构和演示数据由 Flyway 在后端首次启动时自动创建，不要手工重复执行 V1/V2 SQL。

### 3. 配置并启动后端

进入后端目录：

```powershell
cd backend
```

设置当前 PowerShell 窗口的环境变量：

```powershell
$env:SERVER_PORT="8080"
$env:DB_URL="jdbc:mysql://localhost:3306/tax_business?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false"
$env:DB_USERNAME="tax_app"
$env:DB_PASSWORD="ChangeMe_Local_2026"
$env:CORS_ALLOWED_ORIGINS="http://localhost:5173,http://127.0.0.1:5173"
$env:EXPORT_MAX_ROWS="5000"
```

开发模式启动：

```powershell
mvn spring-boot:run
```

看到以下信息说明启动成功：

```text
Started TaxApplication
Tomcat started on port 8080
```

验证：

```text
http://localhost:8080/actuator/health
http://localhost:8080/swagger-ui.html
```

健康检查应返回：

```json
{"status":"UP"}
```

### 4. 配置并启动前端

另开一个 PowerShell 窗口：

```powershell
cd frontend
```

首次安装或依赖变更后执行：

```powershell
npm ci
```

如果当前没有可用的 `package-lock.json`，才使用：

```powershell
npm install
```

启动 Vite：

```powershell
npm run dev
```

访问：

```text
http://127.0.0.1:5173
```

Vite 开发服务器会将 `/api` 代理到：

```text
http://localhost:8080
```

因此本地开发时：

- 浏览器只访问 5173。
- 前端页面由 Vite 提供。
- API 请求由 Vite 代理到 Spring Boot 8080。
- 前后端必须同时运行。

### 5. 使用 JAR 启动后端

先构建：

```powershell
cd backend
mvn clean package
```

产物：

```text
backend\target\tax-business-backend-1.0.0.jar
```

设置环境变量后运行：

```powershell
java -Dfile.encoding=UTF-8 -jar target\tax-business-backend-1.0.0.jar
```

这种方式不会像 `mvn spring-boot:run` 那样依赖 Maven 进程，适合本机演示打包结果。

### 6. 前端构建检查

```powershell
cd frontend
npm run lint
npm run format:check
npm run build
```

构建产物：

```text
frontend\dist
```

Docker 部署会自动把 `dist` 复制到 Nginx。若手工部署到独立 Nginx，需要参考 `frontend/nginx.conf`，并把其中的 `proxy_pass http://backend:8080` 改为实际后端地址或保持 Docker 服务名。

> `npm run dev` 和 `vite preview` 适合本地调试，不建议直接作为公开生产服务。

### 7. 运行后端测试

测试会执行 Flyway `clean + migrate`，必须使用专用测试库：

```powershell
cd backend
$env:TEST_DB_URL="jdbc:mysql://localhost:3306/tax_business_test?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false"
$env:TEST_DB_USERNAME="tax_app"
$env:TEST_DB_PASSWORD="ChangeMe_Local_2026"
mvn test
```

当前文档对应的测试基线为：

```text
28 个测试，0 失败，0 错误
```

> 不要把 `TEST_DB_URL` 指向 `tax_business` 开发库。测试会清理并重建测试数据库中的对象与数据。

## 四、演示账号

本地开发和 Docker 部署使用相同的演示账号，密码统一为：

```text
Demo@1234
```

| 账号 | 角色 | 说明 |
| --- | --- | --- |
| `admin` | 系统管理员 | 用户、角色、全部业务和日志 |
| `clerk` | 业务经办人 | 新建、保存、提交、撤回本人申报 |
| `reviewer` | 审核人员 | 审核待办，不可审核自己创建的申报 |
| `analyst` | 统计分析员 | 查看统计、综合查询和导出 |
| `viewer` | 只读访客 | 只能查看授权页面 |

仅用于课程演示，真实部署前应修改或删除演示账号。

### 自助注册说明

- 登录页切换到“注册账号”页签。
- 填写显示名称、登录账号、密码和确认密码。
- 登录账号长度为 3-64 位，只允许字母、数字、下划线、点和短横线。
- 密码至少 8 位，必须同时包含字母和数字。
- 新账号固定分配 `VIEWER` 只读角色，不能由客户端指定其他角色。
- 注册成功后返回“账号登录”并预填新账号。
- 重复账号返回 409，弱密码或非法格式返回 400。

对应接口：`POST /api/v1/auth/register`，该接口允许匿名访问，并已加入 Spring Security 白名单。

## 七、常见问题排查

### 1. Docker 引擎未运行

打开 Docker Desktop，等待 `Engine running`。

### 2. 首次构建很慢

首次需要下载 Maven、JDK、Node、Nginx 和 MySQL 镜像，并下载前后端依赖。不是程序卡死。

### 3. 18080 或 18081 被占用

复制 `.env.docker.example` 为 `.env`，修改：

```dotenv
APP_PORT=28080
BACKEND_PORT=28081
```

重新执行 `START.bat`。

### 4. 页面打开但接口报错

检查：

```powershell
docker compose ps
docker compose logs --tail=200 backend
docker compose logs --tail=200 frontend
docker compose logs --tail=200 mysql
```

正常情况下三个服务都应为 running/healthy。

### 5. 后端启动但页面 502

Nginx 已启动但后端未健康。等待后端健康检查，或查看 Spring Boot 日志。常见原因是数据库未准备好、数据库账号密码错误或 Flyway 迁移失败。

### 6. 本地前端请求 API 失败

确认：

- 后端已在 8080 启动。
- 前端使用 5173 启动。
- 浏览器访问的是 Vite 地址，而不是直接打开 `dist/index.html`。
- Vite `/api` 代理没有被修改。

### 7. 登录后立即 401

检查：

- 浏览器允许 Cookie。
- 前端请求使用 `withCredentials`。
- Nginx `/api` 代理正确。
- 通过 18080 或 5173 访问，不要混用不同主机名。

### 8. `Access denied for user 'tax_app'`

确认 MySQL 账号、密码和 `GRANT`：

```sql
SHOW GRANTS FOR 'tax_app'@'localhost';
```

并检查当前 PowerShell 窗口中的 `DB_USERNAME`、`DB_PASSWORD` 是否已设置。

### 9. Flyway 校验失败或迁移失败

Flyway 会记录 `flyway_schema_history`。不要手工修改已经执行的 V1/V2 迁移文件来规避校验错误。开发环境可确认不需要旧数据后重建 `tax_business` 数据库，再启动后端。

### 10. 测试把数据库清空

测试配置会执行 `flyway.clean()` 和 `flyway.migrate()`。这是预期行为。务必让 `TEST_DB_URL` 指向 `tax_business_test`，不要指向开发库。

### 11. 两个版本能否同时运行

可以。传统版 Docker 使用 18082，Spring Boot 版使用 18080/18081，数据库容器、数据卷和网络名称也不同。
